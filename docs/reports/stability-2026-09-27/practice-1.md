## Actual missing behavior

1. PRACTICE has no TUTORIAL/TRAINING question. A two-card `HubPracticePopup : HubScreen` can use the existing modal/card builders: Tutorial leaves any room then calls the existing `SceneFlow.StartTraining`; Training calls the existing `StartPractice`. Back pops only the picker. The direct `HubHero.TryInPractice` route may continue entering the free range with its selected hero; it is not the PRACTICE card's two-choice door.
2. No explicit range-only launch state or range panel exists. Use one transient launch marker, cleared by `GameLaunch.Reset`/leave, to distinguish the free range from offline casual and guided training. The range panel should be reached by the existing rebindable Pause action (one keyboard binding, pad Start), with a dedicated touch menu button; a panel action must be refused unless the marker is set, `SceneFlow.Networked` is false, `PracticeSandbox.Allowed` is true, and the local arena is active. Keep the existing pause menu's Resume/Settings/Leave behavior and input parking, cursor release, focus and close cleanup; do not add a second competing Escape reader.
3. The rest of the requested range controls are not hidden features. F1-F6 `DebugPlayerSwitcher` changes the *driven seat*, not that body's person/kit, and has no pad or touch route (`DebugPlayerSwitcher.cs:104-200`). `CharacterIndex`, `HeroAbilitySystem.BindHero` and `CharacterVisual.ApplyModel` are separate install-time steps (`MatchInstaller.cs:775-918`); changing only a saved pick or index mid-match would leave the model, abilities and HUD disagreeing. Bots are built or omitted at install (`MatchInstaller.cs:383-418,1016-1022`), while `RoundDirector` has `Register` but no removal operation. Disabling AI would leave a body in the round and is not "remove bot." No player-facing freeze-can or infinite-stamina state was found; `Stamina.RefillAndClearFatigue` is a one-time refill, not an infinite-stamina policy.

## Implementation boundary

The picker and panel shell are a small existing-control UI integration for the UI owner after file ownership transfers. The panel should show only working actions: reuse `PracticeSandbox.Toggle` for infinite skills/no cooldowns/ultimate full, with current state shown; provide explicit hero/person, can, stamina and bot controls only when their local runtime actions exist. A small range controller may own these local toggles and reset them on exit, but in-place person refresh and bot seat creation/removal cross match installation, visuals, role/round registration and input ownership. They need a reviewed runtime contract (Astra lane), not UI callbacks that mutate `CharacterIndex` or `AIController.enabled` alone. No new network message or wallet/career write should be added. The current QA-16 offline-record guard must still exclude range results while ordinary LAN/casual/ranked results remain eligible.

Focused acceptance: PRACTICE opens the picker; Tutorial and Training enter their distinct existing routes; Escape/pad B/touch Back dismiss only the top card; Pause key/pad Start/touch menu opens and closes the range panel with no stuck input; each displayed control changes the actual local game state and restores it on leave; hero/person swap refreshes body, kit, camera/HUD; summoned bots have the requested seat/role/idle-active state and removal clears round participation; the same controls are absent/refused in offline casual, networked and ranked play; no range career, XP, upload or Tansan is recorded. Render the modal and range panel at the owner's window shape and capture the press path on keyboard, pad and touch. No part of this acceptance has been run yet.
