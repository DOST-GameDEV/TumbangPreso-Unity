# PRACTICE-1 range runtime contract for review

Proposal only. The PRACTICE picker is a separate completed source unit; it does not implement a training range panel or its controls. No range runtime source was changed or run here.

## Lifetime and authority

- Use one explicit, transient free-range launch marker; the current `StartPractice` enters an offline bot match but has no marker that distinguishes it from offline casual or `GuidedTutorial`. Set it only after leaving a room and clear it in the existing match-exit/reset path. Range commands must check that marker, a live local arena, `!SceneFlow.Networked`, `!NetAuthority.IsNetworked`, and `PracticeSandbox.Allowed` at execution time, not only when the panel opens. Refuse a disconnected network arena during teardown via the existing authority-revoked latch. No range action sends an RPC, changes a queue, or writes a wallet/career record.
- The already working `PracticeSandbox.Toggle` owns infinite skills/no cooldowns and replenishes the ultimate meter. Keep that one behavior; do not make a second cheat copy. Other range toggles need explicit on/off state and cleanup on leave, rematch, or scene destruction. Keep the normal match and tournament defaults unchanged. QA-16's offline `MatchRecord.Online`/CareerStore/economy gate remains the no-reward boundary.

## Actions needing a runtime owner

- **Change hero/person in place:** validate a roster pick, release the old kit's active effects and buffered input, then refresh the same seat's `CharacterIndex`, `HeroAbilitySystem.BindHero`, `CharacterVisual.ApplyModel` with its correct palette/clips/pet, viewmodel/camera/HUD/nameplate and selected-person identity together. `MatchInstaller.BuildSeat` currently does these steps only at installation; writing `SettingsStore.CharacterPick` or `CharacterIndex` alone is not a swap. Do not alter the saved pre-match pick unless the player explicitly asks to keep it. Confirm the old ability's owned hazards do not remain after changing.
- **Summon/remove bot:** the range has four indexed seats, but `MatchInstaller` either constructs a seat at entry or omits it when bots are off. `RoundDirector.Register` has no symmetric removal. A bot command must create/remove real seat participation, AI, input ownership, slipper/carrier association, role and round references as one operation; disabling AI or hiding the model is not removal. Protect the human seat and keep at most three bots. "Idle/active" is an AI behavior switch on a present bot; "role" must respect the round's one-defender invariant or define an explicit practice-only override.
- **Freeze the can:** gate the local can simulation/interaction through a reversible practice-only state; do not freeze global `Time.timeScale`, which would stop status timers and the rest of the match. **Infinite stamina:** provide a reversible stamina policy in its owner, not a one-frame call to `RefillAndClearFatigue`. Neither exists as a player-facing range toggle today.

## UI handoff and proof

Once the runtime operations have clear success/refusal results and state reads, the pause-style range panel can use the existing bound Pause action for keyboard/pad, add a touch opener, and reuse `Panel`/`ScreenFocus` for focus, back, input parking and cursor restoration. Show only actions that work. Focused native checks should exercise each action while active, every refusal from offline casual and LAN/Relay/ranked contexts, cleanup after leave/re-entry, a real mid-round hero refresh, bot summon/idle/active/removal with round counts, can/stamina restoration, and zero range XP/history/upload/Tansan. A static getter test or visual-only button click is insufficient for the in-place operations. This runtime unit merits Astra review before UI callbacks are wired.
