# Keep the completed map preview during a cold switch

## Original failure

MapPreviewSurface.Swap parks the old scene immediately, while its camera keeps drawing into the visible render texture during the new additive load. That clears the last useful image into an empty/grey preview. Local native original2 Unity53860 reproduces the one-case failure on actual Eskinita-to-Kanto cold loading, including a visibility refresh. This confirms the pending-camera gap, not every possible cause of grey materials.

## Correction

Freeze the preview camera at swap start and keep its completed render texture visible. Visibility refreshes and camera setup respect the pending state. After the new scene activates, wait one frame for its environment components, configure the intended map shot/environment, render the replacement and only then announce MapShown/resume normal rendering. The existing scene cache, map geometry, lighting art, controls and preview framing are preserved. This avoids the visible gap and useless pending-camera clears; it does not prove cold-load latency is shorter.
