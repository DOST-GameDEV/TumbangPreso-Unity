# Preserve fresh input while retiring background events

Two native defects were reproduced in PlayerInputReader. The first resumed Update recaptured every held button, discarding a genuinely fresh throw generated after the focus callback but before that read. Original source30f29 reproduced one failed fresh throw and one passing background-hold control. Timestamp classification passes those same two cases and the twelve existing interruption/lifetime cases.

The second defect was exposed by a queued background Jump down/up pulse. ReadButton removed its release gate before recovery buffering inspected it, allowing a stale JustPressed recovery edge even with the button released. The timestamp candidate reproduced one failure and one passing fresh-pulse control. Taking the recovery gate before ReadButton passes both.

The final source subscribes to action performed events while enabled and compares their original event times with InputState.currentTime recorded at focus return. Background presses enter the existing release gate; a fresh focused press remains available. The reader unregisters all callbacks when disabled. Recovery buffering uses the gate from before a released button can remove it. Bindings, hero designs, network formats and artwork are unchanged.

The final combined native gate runs all sixteen actual cases across FreshFocusEdgeTests, FocusPulseBoundaryTests, QueuedFocusReturnTests, ReaderBackgroundFocusTests and InputFocusLifetimeTests: sixteen pass, zero fail or skip. It validates the final timestamp plus recovery-order source, not just the intermediate candidate. Fixtures queue real virtual Gamepad events at a LateUpdate boundary and exercise actual reader/Carrier consumers; they do not write private charge or timer values. Existing scene setup is reused.

All six jobs are terminal. Exact launch commands, original failures and final XML/classifications are retained under raw. Every qualified input snapshot is restored, with no unknown input changes, and thirteen existing isolated editor preference values are restored for each job. The first three snapshots contain21138 inputs; the last three21140. Full manifests stay local; qualification records their exact file hashes and the selected final source LF hashes. Unity6000.5.8f1 ran locally on gamergmae Windows11 with graphics, one heavy job at a time, an isolated worker Library and validation profile. No arbitrary memory or elapsed-time admission rule was used.

This narrow gate uses a qualified30f29 worker snapshot plus the recorded fixture/Reader overlays. Publication pulls newer integration commits while comparing all eleven selected production/fixture/meta LF hashes with the tested bytes. It is not a full integration sweep. InputSystem CallbackContext.time is the originating event timestamp in the same realtime clock as InputState.currentTime, verified from the installed package source.

Physical Alt-Tab, keyboard/controller/touch hardware, packaged gameplay and two-machine input acceptance remain open. The current shared4b679 artifact does not include this refinement. Existing LAN/online results remain valid for that exact artifact; they do not qualify this new Reader source. A future matched artifact must include it before the corresponding operator test.
