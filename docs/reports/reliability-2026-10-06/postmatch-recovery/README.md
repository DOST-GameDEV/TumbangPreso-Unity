# Client recovery after host departure

On the same protocol152 package, an untouched laptop client created a new LAN
host after this PC used MAIN MENU following a completed LAN match and again
following a completed public-online match. Both full saved match records remained
identical on both machines. The unwanted rooms were6JKN and KJ9W.

MatchRpc.HandleClientDisconnected routed the client to networked MatchSetup.
The current preparation controller then invoked AutoHost with no live transport.
The correction retires simulation then uses the existing GoHome route for the
current hub, clearing Networked, the requested lobby mode and the pending room
entry. The legacy preparation board retains its existing lobby recovery.

Original consumer tests reproduce both current-hub route failures (mid-match and
completed match) while six lifetime/legacy controls pass. The candidate passes all eight cases. Both native jobs are terminal and all
21126 inputs, shared preferences, Quality settings and isolated profile seeds
were restored byte exactly. Packaged corrected recovery remains unqualified.
