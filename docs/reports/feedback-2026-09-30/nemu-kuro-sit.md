# Nemu Kuro: Sit

## Behavior and scope

The current Wiki signature replaces the former Terrify fear area with Kuro: Sit.
The stable ID remains nemu_skill1. The first cast places a stationary Kuro anchor
for 10 seconds. A second eligible press recalls Nemu to it once without spending
or restarting another cooldown. Expiry, reset and cancellation end the anchor
without teleporting its owner.

The existing 2-to-7-metre hold-to-aim reach is retained because the Wiki supplies
no replacement targeting distance. Existing Kuro art, cast clips, cues and reticle
style are reused. The aim marker now describes one recall spot rather than a
fear area. No authored model, animation, audio or scene asset changed.

CharacterMotor.Teleport retains confinement, owning-client prediction and host
transform delivery. Observing clients cannot move another player's motor.
An inactive round cannot trigger a local recall. The shared 25-second basic
cooldown and 10 percent cooldown movement bonus remain intact.

The ability implements the existing IPreparedWorldReplication route: host
snapshots carry the anchor and remaining lifetime; recovery neither casts again
nor spends cooldown/meter. Authoritative empty state releases the anchor. Invalid
coordinates, preparation time or lifetime are rejected before mutation. Late
model creation adopts the current anchor without resetting it.

Protocol94 prevents a peer that still interprets nemu_skill1 as Terrify from
joining this gameplay version. Every participant needs a matching updated build.
No new packet layout is introduced. Existing prepared-world sender, match, round,
scene, generation, simulation-clock and newer-event guards remain authoritative.

Source: [Wiki, Abilities - Technical](https://docs.google.com/document/d/1jvr7NLzhHrbw-wrG676AeOkoTxJf4GokkfmxpO0ddLg/edit?tab=t.0),
read 2026-09-30. Fetch, Catch, Haunt and remaining kit-definition differences are
still open. The shared Feedback row is not marked complete, and the locally
reserved Feedback/How to use Feedback tabs were not edited.

## Native verification

Unity6000.5.8f1, Linux64, graphics enabled with Mesa llvmpipe, isolated complete
candidate and guarded named cloud-nemu-sit profile.

- Baseline:9 PlayMode cases,3 passed and6 failed. Failures show the Terrify name,
  unavailable recall and missing prepared-world recovery.
- Corrected runtime:the same9 PlayMode cases passed, none failed or skipped.
  They use actual CharacterMotor teleportation and cover one-shot recall without
  cooldown refill, expiry, round reset, recovery without resource spending,
  authoritative empty state, invalid snapshots, observer authority and inactive
  round rejection.
- An additional PlayMode case loaded the actual Nemu/Kuro roster assets, moved
  the owner motor, confirmed Kuro stayed at the anchor, and recalled the owner.
  It passed1/1. This checks real companion transforms, not subjective render taste.
- The related18-case native cooldown/receipt fixture passed18/18 again after the
  signature replacement. Final frozen source hashes remained unchanged.

One baseline-fixture compile repair used the public AbilityContext constructor;
no assertion or production behavior was weakened. The prior compiler log remains
in the isolated evidence. No actual network peers, physical-device checks, full
player build, visual layout judgment or whole-game regression are claimed.
The protected PNG metadata generated by import remains outside published changes.
