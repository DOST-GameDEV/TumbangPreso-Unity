## Integration surfaces to inspect and claim per unit

Existing Runtime/Abilities/<Hero>HeroKit.cs owns definitions and authority entry.
Core rules stay in Packages/com.tumbangpreso.core/Runtime. Slipper/Carrier own real
shoe state and consumption; MatchDirector.AddScore remains sole scoring authority.
HeroKit/HeroAbilitySystem handle role, cooldown and accepted/rejected input. Shared
input bridges remain; prefer existing skill/recast input rather than a new verb.

Movement uses existing CharacterMotor/hero movement contracts, snapshots and
budgets. World objects use WorldEffectSnapshot and render-only RecordedFieldView.
Persistent Overclock needs bounded match-scoped state through current recovery
and replay; no local-only bool that disappears on join or survives a new match.
Any new wire meaning bumps compatibility and updates the matching receiver checks.
Preserve existing stable ability IDs and authored asset GUIDs through migrations.

Visual work starts at the existing HeroAbilityClips.<Hero>, ViewmodelArms action
routes, HeroIntroductionScene.<Hero> and authored UltimateIntros resources.
Inspect actual registrations before introducing another animation path. Audio uses
current AudioCues/NetCue routing and the shared mix, with bounded one-shot/loop
ownership. UI text/glyphs/timers must describe the accepted current role/upgrade,
not an independent guessed duration. Bots use the same intents, reaction limits,
LOS and refusal rules as people; no extra information or instantaneous aiming.

## Minimal meaningful evidence per changed contract

- Pure rules: bounds, cooldown reduction clamping, once-per-event identity,
  scoring-bank cap and round/match lifetime. Core tests do not prove presentation.
- Native behaviour: accepted and refused cast, hit and miss, current role, expiry,
  round exit, object ownership, cancellation and affected existing control case.
- Network: real receiver malformed/stale/duplicate scope and late-join/recovery;
  then actual two-peer checks for changed authority/wire semantics. Do not call
  a receiver unit test a live peer session.
- Presentation: source-frozen named-profile film on actual court, real FPP/victim/
  spectator positions, low and high quality, narrow and wide layouts. No fake
  forced result to make a screenshot prettier.
- Performance/audio: same scene/cast load before and after, active-object/allocation
  checks, listening to overlapping real gameplay events. Compilation proves none
  of these. Note exact limits instead of borrowing old build evidence.

A coherent unit ships explicit owned paths and receipts, then same Feedback row
gets commit and short result. Done is separate from human approval. Human-verified
rows move to existing Finished feedback history with observations intact. A
regression reopens that same row. No duplicate implementation or duplicate report.
