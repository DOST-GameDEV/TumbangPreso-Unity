# Live pause pending-action lifetime

Opening the live match menu parked held input before retiring its consumers.
Carrier, CombatVerbs and generic hero aim could interpret that withdrawal as a
deliberate release. OnOpened now synchronously cancels only pending input before
parking, with offline/local-seat custody. Committed lunge contact and cooldown,
offline speed restoration and received remote hero aim renewal remain intact.
No kit, cooldown, resource, artwork or menu design changes.

Native graphics PlayMode validation used Unity6000.5.8f1 on the laptop, the
isolated qa-d project, Library, editor preference identity and named profile.
The fixture uses the real prepared PausePanel and public Panel.Open entry.
Input is supplied through real TouchInput/PlayerInputReader and live consumers;
this does not claim physical keyboard, touch or controller operator acceptance.

The first baseline ran six cases: three intended pending throw/lunge/hero
failures, two passing controls and one remote-owner fixture precondition failure.
The remote case incorrectly supplied a host provider alongside an attached
reader, which made that body host-driven and ignored received network aim.
One bounded fixture repair uses a client provider for that control and explicitly
clears training state and hitstop during setup. The unchanged production
baseline then reproduced exactly three intended failures and three controls.
Only PausePanel production source was replaced before the same corrected six
cases first passed6/6. Original evidence is retained. Every guard terminated,
restored isolated settings/preferences and released its lease.
