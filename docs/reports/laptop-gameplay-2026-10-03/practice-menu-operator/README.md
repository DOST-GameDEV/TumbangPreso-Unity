## Exercised route

The fixture loads the actual offline range with the saved bots-off option.
It opens the range's prepared PausePanel, scrolls its existing list, opens
`SeatChoice`, and activates a real `Choice2` popup option. It uses the visible
Present toggle and Behaviour popup callbacks, then the Defender popup and
Resume action. It never calls `SetBot` or `SetDefender` directly, seeds range
readiness or replaces the menu hierarchy.

Every activated control must be the first selectable reached by a pointer
raycast at its visible center. Classic dispatches the normal pointer-click
handler; Hero Strike selects the real control and dispatches its submit
handler. This checks callback entry and visible targets, not hardware mouse,
keyboard or gamepad input or MenuNav directional traversal. Both modes use the
same prepared bodies, brains and slippers. The unrelated default bot remains
absent throughout.

The restored attacker must receive the same held shoe. The restored defender
must be the same body with no held shoe and its existing shoe inactive. The
menu keeps time stopped and local input parked throughout editing. Resume must
unpark local input, restore the playing clock, and permit the active bot to
leave its Idle plan within one simulated second. This is bounded planner
liveness, not a physical tag, fresh aim/windup cadence or complete autonomous
gameplay qualification. Launch flags, saved choices, rules and sandbox state
are restored in finally; both fixture hooks reset the world.

## Source reconciliation

Current `PracticeRange.SetBot` removal disables the actor and reaches the
already qualified Carrier/Combat and AI producer hooks. Restoration reuses the
prepared body, clears statuses/kit state, restores its derived role, teleports
and seats it, registers it and reuses the correct attacker shoe. `EquipSeat`
keeps a defender's shoe inactive. The actual UI choice option calls its bound
value callback after closing the popup; opening a choice button alone does not
exercise that callback. No missing OnDisable correction was found or repeated.

This check fills the actual menu acceptance gap recorded in the practice
reconciliation report. Physical-device behavior, victim contact and broader
practice acceptance remain distinct claims until separately tested.
